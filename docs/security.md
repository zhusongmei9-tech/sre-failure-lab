# 部署前安全与质量优化

这一版仍未部署，未替你创建真实账号或保存实际令牌。下面的初始化由你在选定的实验机运行。

## 首次启动：没有默认控制令牌或 Grafana 密码

```bash
python3 scripts/init_env.py
docker compose config --quiet
docker compose up --build -d --wait
```

初始化脚本用系统安全随机数生成两份独立凭据，写入权限为 0600 的 `.env`，不打印内容，
拒绝覆盖已有文件。`.env` 已在 Git 和 Docker 构建忽略规则中。不要发送给他人或提交仓库。
`docker compose config`（不带 `--quiet`）可能打印解析后的秘密，排错分享输出前应脱敏。

如果已经有 `.env`，不要删除它或重置数据卷。对照 `.env.example` 添加强随机 `LAB_TOKEN`
并确认 `GRAFANA_ADMIN_PASSWORD`，保留原有端口和业务设置。已有 Grafana 数据卷的密码
不会因修改环境变量自动改变，须用 Grafana 管理界面处理。初始化脚本不会帮你旋转已有密码。

## 控制面认证

- 直接启动应用时实验功能仍默认关闭。
- 启用 LAB_ENABLED 时必须提供 32–256 个 URL 安全字符的 LAB_TOKEN，否则启动失败。
- 所有 `/lab/*` 路由，包括状态和事件读取，都要求 `Authorization: Bearer <token>`。
- `/docs` 点击 Authorize 填令牌。CLI 在 API 容器内读取环境变量，不在 shell 参数里传实际令牌。
- 健康检查、商品查询和 `/metrics` 仍无认证，适用于回环绑定 + SSH 转发的实验环境。
- 它不是公网认证体系：没有用户账号、角色权限、令牌轮换服务或 TLS 终止。
- Docker 管理员能读取容器环境；该令牌不用于对抗宿主机管理员。不要复用其他服务密码。

## 防误操作与操作记录

控制参数中的未知字段返回 422，避免把 `duration` 拼错后悄悄采用默认时长。
已有应用故障时直接再次注入返回 409；先明确清除再新建。CLI 延续原流程：先校验所有
输入，再认证，最后执行恢复并注入下一项。校验失败或认证失败不会先重启 Redis。

`GET /lab/events?limit=50` 返回最近事件（最多 200）。包括事件 ID、UTC 时间、动作和
非敏感参数。内存采用有界队列，重启丢失；相同记录同时写入 JSON 日志，但日志轮转后也
可能丢失，不是长期审计库。故障到期事件是在下一次检查时记下的“观察时间”，不是精确
截止时刻。没有登录用户，因此事件不能证明具体哪位操作者执行了操作。

## 容器与数据校验

API 保持非 root 用户，增加只读根文件系统、移除 capabilities、禁止提权和 PID 上限。
实际 Docker 兼容性仍待目标 Linux 虚拟机验收，不在此环境静默扩大权限。

缓存数据的商品 ID 必须与请求匹配；即使 JSON 格式正确，串商品的缓存也会被重建，
不把商品 2 返回给商品 1 的请求。Redis 仍只存缓存，不是业务数据源。

uv run --locked ruff check .

## 原后续计划（2026-11-14 更新见 learning-path.md）

以下模拟决策/只读功能现已实现；真实执行、部署及外部通知仍未授权或接入。

1. **受控自愈**：连续失败阈值、冷却时间、最大重试、动作白名单和恢复验证。先做模拟执行，
   再决定真实容器操作的权限方式，不能直接给控制台 Docker socket。
2. **发布前业务验证与回滚**：版本标识、候选实例探测、发布互斥、观察期、失败回切。
   先确认虚拟机资源再选蓝绿方案；首次部署无旧版本不能声称回滚。
3. **SLI/SLO 与错误预算**：明确成功率是否包含 429、观察窗口和目标，再加 burn-rate 告警。
4. **演练报告**：导出配置、时间线、客户端成功率/P95 与恢复证据，避免只有截图。
5. **只读控制台先行**：显示真实状态、资源与操作事件，再逐步接危险按钮与额外确认。

邮件/飞书告警需要你选收件人/渠道；持久化事件需要确定保留期限；真实自动恢复和部署需要
明确目标机器与权限边界。这些不在本次优化中擅自启用。
